# M NEXUS — النظام الداخلي لإدارة المكتب

نظام مغلق للاستخدام الرسمي داخل مكتب M NEXUS للمحاماة والاستشارات القانونية (مدير + محامون).
المواصفة الكاملة للمشروع موجودة في [`docs/PROJECT_SPEC.md`](docs/PROJECT_SPEC.md). هذا الملف يوثّق
**حالة التنفيذ الفعلية** حتى الآن.

---

## حالة التنفيذ — المرحلة الأولى: الأساس

بُني الأساس الكامل للنظام (مصادقة، صلاحيات، سجل تدقيق) مع نموذج عمل كامل من الواجهة إلى الخادم
لوحدتي **العملاء** (مع فحص تعارض المصالح) و**القضايا والملفات**. الوحدات المتبقية (المستندات،
المواعيد، الأرشيف القانوني، ساعات العمل، الفوترة) لم تُبنَ بعد — البنية جاهزة للتوسّع إليها بنفس
النمط.

### ما هو مبني وجاهز للاستخدام

**الأمان والمصادقة**
- PBKDF2-SHA512 (600,000 دورة) لكلمات المرور، بملح فريد لكل مستخدم.
- سياسة كلمة مرور مفروضة في الخادم (12 محرفاً، حرف كبير وصغير ورقم ورمز).
- مصادقة ثنائية TOTP قياسية (RFC 6238)، إلزامية على حساب المدير عبر حارس مسار في الواجهة.
- رمز وصول JWT قصير العمر (30 دقيقة) + رمز تجديد مُدوَّر يُخزَّن مجزَّأً فقط في قاعدة البيانات.
- تمييز صارم بين رموز الجلسة العادية ورموز الأغراض المحدودة (تغيير كلمة المرور / التحقق الثنائي أثناء
  الدخول) — لا يمكن استخدام أحدهما بدل الآخر.
- قفل الحساب 15 دقيقة بعد 5 محاولات دخول فاشلة، وتحديد معدل الطلبات (5 محاولات دخول/5 دقائق لكل IP،
  300 طلب/دقيقة عموماً).
- إنهاء الجلسة تلقائياً بعد 30 دقيقة خمول (من طرف الواجهة).
- ترويسات أمان (HSTS، CSP، X-Frame-Options: DENY، X-Content-Type-Options، Referrer-Policy).
- سجل تدقيق للإضافة فقط — أي محاولة تعديل أو حذف تُرفض في `AppDbContext` نفسه بصرف النظر عن مصدر
  الطلب.

**الصلاحيات** — مطبَّقة في `backend/Security/Permissions.cs` وفي كل Endpoint عبر
`RequireAuthorization("ManagerOnly")`: المحامي يملك العملاء والقضايا كاملة، ويبقى إدارة المستخدمين
وسجل التدقيق والحذف النهائي حكراً على المدير.

**وحدات العمل**
- **العملاء**: إنشاء وتعديل وأرشفة، مع بحث فوري وفحص تعارض مصالح حي أثناء كتابة الاسم (يبحث في
  العملاء الحاليين وفي أسماء الأطراف المقابلة بالقضايا القائمة).
- **القضايا والملفات**: إنشاء بترقيم تلقائي (`C-YYYY-NNNN`)، ربط بعميل ومحامٍ مسؤول، تغيير الحالة
  (مفتوحة/مغلقة/مؤرشفة)، وحذف نهائي حكراً على المدير.
- **إدارة المستخدمين**: إضافة/تعطيل/تفعيل مستخدمين، إعادة تعيين كلمة مرور مؤقتة (لا استعادة عبر
  البريد عمداً — المدير يعيد التعيين يدوياً).
- **سجل التدقيق**: عرض مُرقَّم للقراءة فقط، حكر على المدير.

### ما لم يُبنَ بعد (الخطوة التالية)

- المستندات والعقود (رفع/تشفير AES-256-GCM/أرشفة).
- الجدولة والمواعيد (بلا إشعارات بعد).
- الأرشيف القانوني للأنظمة والقرارات.
- ساعات العمل والفوترة (بما فيها هيكل الفاتورة الإلكترونية ورمز QR).
- إعدادات المكتب.

كل وحدة من هذه تُبنى بنفس النمط: كيان في `Domain/Entities.cs`، تهيئة في `AppDbContext`، Endpoint في
`Endpoints/`، وشاشات Vue في `frontend/src/views/`.

## التشغيل السريع (بيئة التطوير)

**المتطلبات:** .NET SDK 9، Node.js 20+، Docker (لقاعدة البيانات).

```bash
# 1) قاعدة البيانات
docker run -d --name mhd-legal-db -p 1433:1433 \
  -e ACCEPT_EULA=Y -e MSSQL_SA_PASSWORD='Dev_Passw0rd!2026' -e MSSQL_PID=Express \
  mcr.microsoft.com/mssql/server:2022-latest

# 2) الخادم
cd backend
dotnet tool install --global dotnet-ef   # مرة واحدة فقط
dotnet ef migrations add Initial
dotnet run                               # ينشئ الجداول ويهيّئ حساب المدير تلقائياً

# 3) الواجهة (نافذة طرفية أخرى)
cd frontend
npm install
npm run dev                              # http://localhost:5173
```

**أول دخول:** البريد `manager@firm.sa` وكلمة المرور `Manager#2026Temp!` (من
`backend/appsettings.Development.json` — بيانات تطوير فقط، غيّرها فوراً في أول دخول كما يفرض النظام).

> **تنبيه:** لم يتسنَّ تشغيل `dotnet build` فعلياً في بيئة إعداد هذا الكود لعدم توفر .NET SDK فيها.
> راجع الكود عند أول تشغيل فعلي، ونفّذ `dotnet ef migrations add Initial` كخطوة أولى إلزامية —
> لا توجد هجرات مُنشأة مسبقاً في المستودع.

## النشر للإنتاج

```bash
cp .env.example .env             # املأ كل القيم
openssl rand -base64 48          # → JWT_KEY
openssl rand -base64 32          # → STORAGE_KEY (32 بايت بالضبط، لتشفير الحقول الحساسة)
mkdir certs                      # ضع fullchain.pem و privkey.pem
docker compose up -d --build
```

قائمة ما يجب فعله قبل أول استخدام حقيقي بالكامل موجودة في [`docs/PROJECT_SPEC.md`](docs/PROJECT_SPEC.md#4-النشر-للإنتاج)
(استضافة داخل المملكة، TDE، نسخ احتياطية مختبرة، سياسة خصوصية، إلخ).

## ملاحظة نظامية

النظام يخزّن بيانات شخصية لعملاء. هذا يُخضع المكتب لنظام حماية البيانات الشخصية ولائحته التنفيذية،
إلى جانب واجب السرية المهنية بموجب نظام المحاماة. راجع قسم "قسم التحقق" في `docs/PROJECT_SPEC.md` —
هذا مستند تقني لا استشارة قانونية.
