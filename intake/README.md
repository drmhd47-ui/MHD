# خادم الاستقبال

خدمة صغيرة (Node.js 22، اعتمادية واحدة: nodemailer) تستقبل نموذج "اطلب استشارة" من الموقع العام،
وتسلّمه إلى النظام الداخلي. تُنشر مع الموقع على الخادم العام، ولا تملك أي وصول إلى قاعدة بيانات المكتب.

## ما تفعله بالترتيب

1. ترفض أي طلب من نطاق غير الموقع (`ALLOWED_ORIGINS`)، أو أكبر من 8 كيلوبايت.
2. تحدد المعدل لكل عنوان IP في الذاكرة (5 في الساعة، 20 في اليوم افتراضياً) — لا يُخزَّن العنوان.
3. حقل فخ مخفي وزمن تعبئة أدنى: الإرسال الآلي يتلقى نجاحاً شكلياً ولا يُحفظ.
4. تتحقق من الحقول (الاسم، ووسيلة التواصل، وجوال سعودي أو بريد، والموافقة على سياسة الخصوصية)،
   وتتحقق من الخدمة مقابل فهرس الموقع (`dist/data/services.json`).
5. تحفظ الطلب مشفّراً (AES-256-GCM) في صندوق صادر على القرص، ثم ترد على المتصفح (JSON، أو تحويل 303
   عند تعطيل JavaScript).
6. ترسل للعميل رسالة تأكيد آلية إن أعطى بريداً: رقم الطلب فقط، بلا أي محتوى قانوني.
7. تسلّم الطلب إلى `INTERNAL_API_URL` بتوقيع HMAC-SHA256، وتحذفه فور التأكيد. عند تعذر الاتصال تعيد كل
   15 ثانية، وتحذفه بعد 7 أيام إن لم يُسلَّم. الرفض النهائي (4xx) ينقله إلى `dead-letter` للمراجعة اليدوية.

## الإعدادات

انظر `deploy/public/.env.example`. `INTAKE_ENCRYPTION_KEY` و`INTAKE_SHARED_SECRET` و`INTERNAL_API_URL` إلزامية.

## الاختبارات

```bash
npm ci && npm test
```

تغطي: توحيد أرقام الجوال، والتحقق، وتنظيف المدخلات، والفخ، وتحديد المعدل، وخلو الرد الآلي من أي محتوى قانوني
أو بيانات مُدخلة، ومساراً كاملاً (استلام ← تشفير ← تسليم موقَّع ← حذف)، وبقاء الطلب عند تعطل النظام الداخلي.
عقد التوقيع وشكل الطلب مُثبَّتان أيضاً من جهة النظام الداخلي في `backend.Tests/CrossServiceContractTests.cs`.
