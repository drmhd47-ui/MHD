# النظام الداخلي لشركة المحاماة والاستشارات القانونية

نظام مغلق للاستخدام الرسمي داخل المكتب (مدير + ثلاثة محامين)، يغطي: القضايا والملفات، العملاء وفحص
تعارض المصالح، الجدولة والمواعيد، أرشيف المستندات والعقود، الأرشيف القانوني للأنظمة والقرارات،
الفوترة والمدفوعات، وسجل التدقيق.

> **ملاحظة:** هذا الملف هو المواصفة الأصلية للنظام الداخلي لمجموعة إم القانونية كما وُضعت قبل بدء التنفيذ. حالة التنفيذ
> الفعلية والفروق عن هذه المواصفة موثّقة في `README.md` بجذر المستودع.

---

## 1. القرارات التقنية

اخترتَ **الخيار الثاني (Stack مستقر وموثوق)**، وقد نُفّذ كما هو مع تعديلين أوصي بهما صراحةً:

| العنصر | ما اخترتَه | ما نُفّذ | السبب |
|---|---|---|---|
| الواجهة | Vue.js + TypeScript | Vue 3 + TypeScript + Vite + Tailwind | كما هو |
| الخادم | C# (.NET) + SQL Server | .NET 9 + EF Core + SQL Server 2022 Express | كما هو (Express مجاني ويكفي 4 مستخدمين) |
| الاستضافة | Azure / AWS | حاويات Docker تعمل على أي مزوّد | **يجب أن تكون منطقة الاستضافة داخل المملكة** |
| المصادقة | Windows AD + MFA | JWT + TOTP (مصادقة ثنائية) | **AD لا معنى له لأربعة مستخدمين** — يستلزم خادم دليل ورخصة وإدارة دائمة لعائد صفري. TOTP يعطي نفس مستوى الحماية بلا بنية تحتية |

**التعديل الثاني الموصى به:** لا تطبيق جوّال أصلي (Native App) في هذه المرحلة. الواجهة مستجيبة بالكامل
وتعمل على الجوال من المتصفح. تطبيق متجر لأربعة مستخدمين يعني تكلفة تطوير وتوقيع ونشر ومراجعة مقابل
لا شيء عملياً. أعد النظر فيه إذا فتحتم بوابة عملاء لاحقاً.

## 2. ثلاث ملاحظات مهنية قبل التشغيل

**أولاً — "جميع الصلاحيات للمحامين عدا الفوترة" فيها فجوة.** طبّقتُ طلبك، لكن استثنيتُ معه ثلاثة أمور
بقيت للمدير وحده لأنها ليست وظائف عمل بل أدوات سيطرة على النظام نفسه:

- **إدارة المستخدمين**: لو ملكها محامٍ لاستطاع رفع صلاحية نفسه إلى مدير ورؤية الفوترة — أي أن استثناء
  الفوترة يصبح بلا معنى.
- **سجل التدقيق**: من يملك مسحه يستطيع إخفاء أثره.
- **الحذف النهائي للسجلات**: المحامون يملكون الأرشفة (استرجاعها ممكن)، لا المحو.

ما عدا ذلك، المحامي يملك كل شيء فعلاً: إنشاء وتعديل العملاء والملفات والمستندات والمواعيد والأرشيف
القانوني وساعات العمل. إن أردتَ منح المحامين أياً من الثلاثة، التعديل سطر واحد في
`backend/Security/Permissions.cs`.

**ثانياً — الفاتورة الإلكترونية.** النظام يبني الفاتورة بكل حقولها النظامية ويولّد رمز QR بصيغة TLV
(اسم البائع، الرقم الضريبي، التاريخ، الإجمالي، مبلغ الضريبة). لكن **الربط الفعلي مع منصة "فاتورة"
في المرحلة الثانية يستلزم شهادة CSID وتوقيعاً رقمياً عبر مزوّد معتمد** — لا يمكن لأي نظام داخلي أن
يوفّرها من تلقاء نفسه. البنية جاهزة لاستقبال الربط، والحقول محجوزة في قاعدة البيانات. تحقق من متطلبات
هيئة الزكاة والضريبة والجمارك السارية وقت التشغيل، فالمواعيد والمراحل تُحدَّث دورياً.

**ثالثاً — مسؤولية نظامية تسبق التقنية.** النظام يخزّن بيانات شخصية لعملاء (هويات، عناوين، وقائع
قضايا). هذا يُخضع المكتب لنظام حماية البيانات الشخصية ولائحته التنفيذية: سياسة خصوصية معلنة، أساس
نظامي للمعالجة، مدة احتفاظ محددة، والإفصاح عن أي تسريب. وإلى جانب ذلك يبقى واجب السرية المهنية بموجب
نظام المحاماة قائماً بذاته وأشد أثراً. التزم بالاثنين، ولا تعتبر الشهادة التقنية بديلاً عن الالتزام
النظامي.

## 3. التشغيل السريع (بيئة التطوير)

**المتطلبات:** .NET SDK 9، Node.js 20+، Docker (لقاعدة البيانات).

```bash
# 1) قاعدة البيانات
docker run -d --name legal-db -p 1433:1433 \
  -e ACCEPT_EULA=Y -e MSSQL_SA_PASSWORD='Dev_Passw0rd!2026' -e MSSQL_PID=Express \
  mcr.microsoft.com/mssql/server:2022-latest

# 2) إنشاء أول هجرة لقاعدة البيانات
cd backend
dotnet tool install --global dotnet-ef
dotnet ef migrations add Initial
dotnet run                       # سينشئ الجداول ويهيّئ حساب المدير تلقائياً

# 3) الواجهة (نافذة طرفية أخرى)
cd frontend
npm install
npm run dev                      # http://localhost:5173
```

**أول دخول:** البريد `manager@firm.sa` وكلمة المرور `Manager#2026Temp!`
(من `appsettings.Development.json`). سيطلب النظام تغييرها فوراً ثم تفعيل المصادقة الثنائية.

## 4. النشر للإنتاج

```bash
cp .env.example .env             # املأ كل القيم
openssl rand -base64 48          # → JWT_KEY
openssl rand -base64 32          # → STORAGE_KEY  (32 بايت بالضبط)
mkdir certs                      # ضع fullchain.pem و privkey.pem
docker compose up -d --build
```

**تحذير جوهري:** `STORAGE_KEY` هو مفتاح فك تشفير كل المستندات. لو فُقد، لا يمكن استرجاع أي ملف مرفوع
بأي وسيلة. احتفظ بنسخة منه في مكان آمن مستقل عن الخادم (خزنة مادية أو خدمة إدارة مفاتيح).

**قائمة ما يجب فعله قبل أول استخدام حقيقي:**

- [ ] استضافة الخادم وقاعدة البيانات **داخل المملكة** (منطقة سعودية لدى المزوّد).
- [ ] شهادة TLS صالحة (نطاق فرعي خاص بالمكتب، لا IP).
- [ ] تفعيل التشفير على مستوى قاعدة البيانات (TDE) وتشفير القرص.
- [ ] نسخ احتياطية يومية **مشفّرة ومخزّنة خارج الخادم**، مع اختبار استرجاع فعلي مرة كل ربع سنة —
      نسخة لم تُختبر ليست نسخة.
- [ ] تفعيل المصادقة الثنائية لكل المستخدمين لا المدير وحده.
- [ ] تقييد الوصول للخادم بجدار ناري، وإغلاق منفذ قاعدة البيانات عن الإنترنت تماماً.
- [ ] سياسة خصوصية معلنة للعملاء وسجل معالجة بيانات.
- [ ] اتفاقية سرية موقّعة مع أي مزوّد استضافة أو دعم تقني يصل للبيانات.

عند كل طلب. الطبقة الثالثة وحدها هي الحماية الحقيقية — الأوليان للراحة فقط.

## 6. ما بُني في الأمن

| الطبقة | التنفيذ |
|---|---|
| كلمات المرور | PBKDF2-SHA512 بـ 600,000 دورة + ملح لكل مستخدم |
| سياسة كلمة المرور | 12 محرفاً فأكثر، أحرف كبيرة وصغيرة ورقم ورمز |
| المصادقة الثنائية | TOTP قياسي (RFC 6238)، إلزامي على حساب المدير |
| الجلسات | رمز وصول قصير (30 دقيقة) + رمز تجديد مُدوَّر ومخزَّن مجزَّأً |
| قفل الحساب | إيقاف 15 دقيقة بعد 5 محاولات فاشلة |
| الخمول | إنهاء الجلسة تلقائياً بعد 30 دقيقة |
| تحديد المعدل | 5 محاولات دخول/5 دقائق لكل IP، و300 طلب/دقيقة عموماً |
| المستندات | تشفير AES-256-GCM على القرص + بصمة SHA-256 تكشف أي عبث |
| رفع الملفات | قائمة امتدادات مسموحة فقط، حد 50 ميجابايت، رفض التنفيذيات |
| سجل التدقيق | إضافة فقط — التعديل والحذف مرفوضان في الكود نفسه |
| الترويسات | HSTS، CSP، nosniff، DENY للتأطير، no-referrer |
| قاعدة البيانات | لا حذف فعلي للسجلات المالية؛ الفاتورة المُصدَرة غير قابلة للتعديل |

**ما لم يُبنَ عمداً ويجب أن تعرفه:** لا استعادة كلمة مرور عبر البريد (ثغرة شائعة — المدير هو من يعيد
التعيين يدوياً)، ولا تسجيل دخول عبر حسابات خارجية، ولا مشاركة روابط عامة للمستندات.

## 8. الخطوات التالية المقترحة (بعد استقرار النواة)

1. **إشعارات المواعيد** عبر البريد أو رسالة نصية — النظام يسجّل `ReminderMinutesBefore` لكنه لا يرسل بعد.
2. **توليد PDF للفواتير** بدل الطباعة من المتصفح.
3. **الربط الفعلي مع منصة الفوترة الإلكترونية** عبر مزوّد معتمد.
4. **بوابة العملاء** (نطاق منفصل، صلاحيات قراءة فقط) — أجّلها حتى تستقر العمليات الداخلية ستة أشهر.
5. **الموقع التعريفي العام** — منفصل تماماً عن هذا النظام وعلى خادم مستقل. لا تضع أبداً موقعاً عاماً
   على الخادم الذي يحمل ملفات العملاء.

## قسم التحقق

- **المتطلبات النظامية المشار إليها** (حماية البيانات الشخصية، الفوترة الإلكترونية، السرية المهنية
  بموجب نظام المحاماة) مذكورة على مستوى المبدأ العام. **الأحكام التفصيلية والمهل والاشتراطات الفنية
  تُحدَّث دورياً**، ويجب التحقق من نصوصها السارية وقت التنفيذ الفعلي من مصادرها الرسمية: هيئة الزكاة
  والضريبة والجمارك، الهيئة السعودية للبيانات والذكاء الاصطناعي، الهيئة الوطنية للأمن السيبراني،
  والهيئة السعودية للمحامين.
- **هذا المستند تقني لا استشارة قانونية.** قبل تشغيل النظام على بيانات عملاء حقيقية، اعرض ترتيبات
  الاستضافة والاحتفاظ والوصول على مختص امتثال، خصوصاً إن كان بين العملاء جهات حكومية لها اشتراطات
  تعاقدية خاصة بموقع البيانات.
- **الضوابط الأمنية المذكورة في القسم السادس منفّذة فعلياً في الكود** ويمكن مراجعتها في الملفات المشار
  إليها، لكنها لا تُغني عن اختبار اختراق مستقل قبل الاعتماد على النظام في العمل الفعلي.
