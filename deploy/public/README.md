# نشر الموقع العام وخادم الاستقبال

يُنشر على **خادم مستقل داخل المملكة**، غير خادم النظام الداخلي (المواصفة، البند 8-5). سياسة الخصوصية
المنشورة تنص على أن الاستضافة داخل المملكة؛ إن تغيّر ذلك يجب تعديل السياسة قبل النشر.

## الخطوات

```bash
cp deploy/public/.env.example deploy/public/.env      # املأ القيم
openssl rand -base64 32    # → INTAKE_ENCRYPTION_KEY
openssl rand -base64 48    # → INTAKE_SHARED_SECRET (نفس القيمة في .env النظام الداخلي)
mkdir deploy/public/certs  # fullchain.pem و privkey.pem لنطاقي mgrp.sa و www.mgrp.sa
docker compose -f deploy/public/docker-compose.yml --env-file deploy/public/.env up -d --build
```

## الربط بالنظام الداخلي

- `INTERNAL_API_URL` يشير إلى `https://<الخادم الداخلي>/api/internal/intake-requests` **عبر شبكة خاصة**
  (VPN موقع-إلى-موقع أو شبكة افتراضية خاصة لدى مزود الاستضافة)، لا عبر الإنترنت العام.
- nginx النظام الداخلي (`frontend/nginx.conf`) يقبل هذا المسار من النطاقات الخاصة فقط؛ عدّلها لتطابق عنوان
  خادم الاستقبال تحديداً.
- كل رسالة موقّعة بالسر المشترك، ويُرفض أي فرق توقيت يتجاوز 5 دقائق — اضبط مزامنة الوقت (NTP) على الخادمين.
- حدد المحامي المناوب في النظام الداخلي: إعدادات المكتب ← "المحامي المناوب لطلبات الموقع"، واضبط `Smtp__*`
  في النظام الداخلي ليصله الإشعار.

## قائمة ما قبل الإطلاق

- [ ] استضافة الخادمين داخل المملكة.
- [ ] شهادة TLS صالحة، وتحويل `mgrp.sa` و`http` إلى `https://www.mgrp.sa`.
- [ ] تدوير سجلات nginx وحذفها بعد 30 يوماً (logrotate على وحدة `web-logs`: `rotate 30` و`daily`)، كما
      تنص سياسة الخصوصية.
- [ ] نسخ احتياطي لوحدة `intake-data` غير مطلوب (بيانات عابرة)، لكن راقب مجلد `dead-letter`.
- [ ] مزود SMTP للرد الآلي (عنوان `no-reply@mgrp.sa` مع SPF وDKIM).
- [ ] إرسال طلب تجريبي والتأكد من ظهوره في "طلبات الموقع" بالنظام الداخلي ووصول الإشعار.
- [ ] تسجيل الموقع في Google Search Console وإرسال `https://www.mgrp.sa/sitemap-index.xml`.
- [ ] مراجعة محامٍ مرخّص لنصوص الخدمات والسياسات قبل النشر.

## ما تم التحقق منه في بيئة التطوير

- `nginx -t` على هذا الملف (بنسخة nginx أقدم لا تعرف `http2 on;`، فحُذف ذلك السطر لأجل الفحص فقط؛ صورة
  `nginx:1.27` في Dockerfile تدعمه).
- التحويل من `/` إلى `/ar/`، وترويسات الأمان وCSP، وصفحة 404، وحجب `/api/*` عدا `/api/intake`، وتمرير
  النموذج إلى خادم الاستقبال وعودته بتحويل 303 إلى صفحة الشكر.
- تحميل الصفحات في Chromium تحت CSP بلا أي خطأ، وعمل القائمة وإغلاقها بـ Escape، وتحميل الخط الرسمي محلياً.
